# Handover AI

**AI Nursing Handover Assistant** — 看護申し送り業務を支援するWebアプリのプロトタイプです。

音声／テキストで入力した勤務中の記録を AI が整理し、**SBAR**・**リスク抽出**・**次勤務への観察項目**・**口頭申し送り用の要約**を生成します。生成結果は編集・読み上げ・コピーができ、申し送り完了までを一連で扱えます。

> ⚠️ ポートフォリオ掲載用のプロトタイプです。表示・保存されるデータはすべて架空であり、実運用を想定したものではありません。

---

## Handover AIとは

病棟看護師の申し送りでは、限られた時間の中で患者ごとの状態変化・リスク・引き継ぎ事項を漏れなく伝える必要があります。Handover AI は次の課題の軽減を狙っています。

- 情報の**抜け**（伝え忘れ）
- 情報の**重複**（同じ内容を複数人が繰り返す）
- **伝達漏れ**（次勤務者が観察すべき項目が共有されない）

そのために、入力された記録から機械的にリスク判定を行い、SBAR形式に構造化して、次勤務者向けのチェックリストまで自動生成します。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| Dashboard | 本日の患者数 / 申し送り完了 / 未完了 / 要注意患者のサマリーと患者一覧（状況・リスクでのフィルタ付き） |
| 患者基本情報 | 氏名・年齢・性別・病室・患者ID・主病名・入院日・担当医・ADL・アレルギー・コードステータス・感染対策・転倒リスクの表示と編集 |
| 申し送り入力 | 自由記載テキストエリア＋構造化入力（バイタル5項目・意識状態・疼痛・食事・水分・排泄・睡眠・点滴・内服・処置・検査・医師指示・家族対応・その他）。併用可能 |
| 音声入力 | Web Speech API による音声認識。認識結果を自由記載へ追記 |
| AI申し送り生成 | 要約 / SBAR / リスク・注意事項 / 次勤務で確認する項目 を生成（ローディング表示あり） |
| SBAR | S・B・A・R を独立カードで表示。生成後に手動編集可能 |
| リスク自動抽出 | 転倒・発熱・SpO2低下・呼吸状態悪化・食事摂取低下・脱水・尿量低下・疼痛増強・アレルギー・ルートトラブル・急変リスクなどを LOW / MEDIUM / HIGH で判定し、判定根拠を併記 |
| 次勤務への観察項目 | リスクに応じた観察項目をチェックボックス形式で生成。チェック状態は保存される |
| Brief Summary | 30〜60秒程度で口頭申し送りできる要約。手動編集可能 |
| 音声読み上げ | SpeechSynthesis による読み上げ（開始 / 一時停止 / 再開 / 停止）。Brief Summary と SBAR全文を切替可能 |
| 申し送り完了 | ステータスを 未完了 ⇄ 完了 に切替。Dashboardの集計へ即反映 |
| 保存 | 患者データ・入力・生成結果・チェック状態・完了状態を localStorage に保存。「デモデータに戻す」ボタンあり |
| コピー | Brief Summary / SBAR / リスク一覧 / 観察項目 の個別コピーと、全体をまとめた「申し送り全文をコピー」。成功時はトースト通知 |
| ダークモード | ヘッダー右上から切替。設定は保存され、初回はOSの設定に追従 |

## 技術構成

- **Next.js 16**（App Router）
- **TypeScript**（strict）
- **Tailwind CSS v4**
- **React 19**
- **lucide-react**（アイコン）
- Route Handler（`/api/handover`）によるサーバー側AI処理

追加ライブラリは lucide-react のみです。状態管理ライブラリやUIフレームワークは使用せず、React標準の `useSyncExternalStore` による軽量ストアと localStorage で構成しています。

## 音声入力について

- ブラウザの **Web Speech API**（`SpeechRecognition` / `webkitSpeechRecognition`）を使用しています。両方の実装名に対応しています。
- 「音声入力を開始」で録音を開始し、録音中は赤いインジケーターと停止ボタンを表示します。認識途中のテキストもリアルタイムに表示されます。
- 確定した認識結果は自由記載のテキストエリアへ追記されます。
- **音声データはブラウザ内で処理され、このアプリのサーバーには送信も保存もされません。**
- 非対応ブラウザでは「このブラウザでは音声入力を利用できません」と表示されます。
- 動作確認済み: Google Chrome / Microsoft Edge。Firefox は現時点で `SpeechRecognition` に未対応です。
- マイク使用の許可が必要です。また、多くのブラウザで `https` または `localhost` でのみ動作します。

## 音声読み上げについて

- **SpeechSynthesis API** を使用しています。
- `speechSynthesis.getVoices()` から `ja-JP` の音声を優先して選択します。日本語音声が見つからない場合はブラウザ既定の音声を使用します。
- 読み上げ対象は **Brief Summary** と **SBAR全文** から選択できます。
- 操作は 読み上げ開始 / 一時停止 / 再開 / 停止 の4つです。
- 非対応ブラウザでは「このブラウザでは音声読み上げを利用できません」と表示されます。
- OSに日本語音声がインストールされていない場合、読み上げが不自然になることがあります（macOS: システム設定 → アクセシビリティ → 読み上げコンテンツ、Windows: 設定 → 時刻と言語 → 音声認識 から追加できます）。

## AI APIについて

AI処理は **UIから完全に分離** されており、`src/lib/handover-ai.ts` が唯一のエントリポイントです。

```ts
generateHandover(input)        // 要約・SBAR・リスク・観察項目を一括生成
generateSBAR(input, risks?)    // SBAR
detectRisks(input)             // リスク抽出
generateNextShiftTasks(input)  // 次勤務への観察項目
generateBriefSummary(input)    // 口頭申し送り用の要約
```

### APIキー未設定時（既定）

`OPENAI_API_KEY` が設定されていない場合は、**モックAIエンジン**（`src/lib/ai/mock-engine.ts`）が動作します。単語の一致だけでなく、数値条件と組み合わせ条件でリスクを判定します。

判定ルールの例:

| 条件 | 判定 |
| --- | --- |
| 「ふらつき」等 ＋ 「夜間トイレ」等 | 転倒リスク **HIGH** |
| 最高体温 38.5℃ 以上 | 発熱 **HIGH**（解熱の記載があれば MEDIUM に緩和） |
| 最高体温 37.5〜38.4℃ | 発熱 **MEDIUM** |
| SpO2 92% 以下 | SpO2低下 **HIGH** |
| SpO2 93〜94% | SpO2低下 **MEDIUM** |
| 呼吸数 25回/分以上 または 9回/分以下 | 呼吸状態悪化 **HIGH** |
| 食事摂取量 3割以下 | 食事摂取低下 **HIGH** |
| NRS 7以上 | 疼痛増強 **HIGH** |
| 収縮期血圧 90mmHg未満 / 脈拍 120以上 | 循環動態の変動 **HIGH** |
| ルート記載 ＋ 「自己抜去」「漏れ」「腫脹」等 | ルートトラブル **HIGH** |
| HIGH判定が2件以上 | 急変リスク **HIGH** を追加 |

各リスクには判定根拠（どの数値・記載から判定したか）が併記されます。

### 実AI APIへ接続する場合

`.env.local` に次を設定すると、`/api/handover` が OpenAI互換APIを呼び出します。

```bash
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini          # 任意
OPENAI_BASE_URL=https://api.openai.com/v1  # 任意（互換APIを使う場合）
```

- APIキーは **サーバー側の Route Handler でのみ** 読み取られ、フロントエンドのコードやバンドルには一切含まれません。
- API呼び出しに失敗した場合はモックAIへ自動フォールバックし、デモが止まらないようにしています。
- 実装は `src/lib/ai/openai-provider.ts` に分離しているため、別のプロバイダへの差し替えも容易です。

## デモデータについて

- **12名の架空患者**（誤嚥性肺炎 / 心不全 / 大腿骨頸部骨折術後 / 糖尿病 / 脳梗塞 / COPD / 胆嚢摘出術後 / 腎盂腎炎 / 気管支喘息 / 前立腺肥大症 / 関節リウマチ / 胃潰瘍）を用意しています。
- 一部の患者にはあらかじめ転倒リスク HIGH などの注意リスクと、申し送り入力の例文を設定しています。
- すべてのデータは **localStorage**（キー: `handover-ai:state:v1`）に保存され、ページを再読み込みしても保持されます。
- Dashboard の「デモデータに戻す」ボタンで初期状態へリセットできます。
- 実在の人物・症例とは一切関係ありません。

## 医療安全上の注意

> **Handover AIは看護申し送りを支援するプロトタイプです。AI生成内容は参考情報であり、最終的な判断・確認は医療従事者が行ってください。**
>
> **実在患者の個人情報を入力しないでください。**

- 本アプリは医療機器ではなく、診断・治療の判断を行うものではありません。
- リスク判定は入力されたテキストに対する機械的な処理であり、臨床判断の代替にはなりません。抽出されないリスクが存在し得ます。
- データはブラウザの localStorage にのみ保存され、サーバーには保存されません。共用端末での利用時はご注意ください。
- 実運用にあたっては、電子カルテ連携・アクセス制御・監査ログ・院内のセキュリティ要件への適合が別途必要です。

- **多言語対応** — 外国人スタッフ向けの英語表示
