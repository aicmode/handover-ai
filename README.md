# Handover AI

**AI Nursing Handover Assistant** — 看護申し送り業務を支援するWebアプリのプロトタイプです。

音声／テキストで入力した勤務中の記録を AI が整理し、**SBAR**・**確認優先度の抽出**・**次勤務への確認候補**・**口頭申し送り用の要約**を生成します。生成結果は編集・読み上げ・コピーができ、申し送り完了までを一連で扱えます。

> ⚠️ ポートフォリオ掲載用のプロトタイプです。表示・保存されるデータはすべて架空であり、実運用を想定したものではありません。

> **AIは診断・治療・看護判断を代替しません。** 本アプリのAIは「入力された申し送り情報を整理し、確認候補を提示する」支援システムとして設計しています。診断名の断定、新しい看護指示・観察頻度・投与基準の作成は行いません。閾値は入力された医師指示に書かれている値のみを引用します。

## Handover AIとは

病棟看護師の申し送りでは、限られた時間の中で患者ごとの状態変化・リスク・引き継ぎ事項を漏れなく伝える必要があります。Handover AI は次の課題の軽減を狙っています。

- 情報の**抜け**（伝え忘れ）
- 情報の**重複**（同じ内容を複数人が繰り返す）
- **伝達漏れ**（次勤務者が観察すべき項目が共有されない）

そのために、入力された記録から機械的にリスク判定を行い、SBAR形式に構造化して、次勤務者向けのチェックリストまで自動生成します。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| Dashboard | 本日の患者数 / 申し送り完了 / 未完了 / 要確認患者のサマリーと患者一覧（状況・確認優先度でのフィルタ付き） |
| 患者基本情報 | 重要情報（氏名・病室・主病名・登録アレルギー・コードステータス・転倒リスク）を先頭にコンパクト表示し、その他の情報は折りたたみ。すべて編集可能 |
| 申し送り入力 | 自由記載テキストエリア（常時表示）＋構造化入力。構造化入力は「バイタル・観察 / 生活状況 / 治療・処置 / 指示・連携」のカテゴリ単位で開閉でき、入力済み件数をバッジ表示 |
| 音声入力 | Web Speech API による音声認識。認識結果を自由記載へ追記 |
| AI申し送り生成 | 要約 / SBAR / 確認優先度 / 次勤務での確認候補 を生成（ローディング表示あり）。生成完了後は結果セクションへ自動スクロール |
| AI生成ドラフト表示 | 生成結果の先頭に「AI Generated Draft — AI生成ドラフト」バッジと、確認・編集を促す注意書きを表示 |
| High Priority | HIGH の確認候補と登録アレルギー、入力済み医師指示（原文）を Brief Summary 直下にまとめて表示 |
| SBAR | S・B・A・R を独立カードで表示。生成後に手動編集可能。Recommendation は「入力済み医師指示（原文）」＋「次勤務での確認候補」で構成 |
| 確認優先度の抽出 | 体温・再発熱 / SpO2値・推移 / 呼吸状態の変化 / 転倒関連 / 食事摂取量 / 水分出納 / 排尿状況 / 疼痛 / 血圧・脈拍 / 意識状態 / ルート・刺入部 / 登録アレルギー / 感染対策 などの確認候補を HIGH / MEDIUM / LOW で提示し、「入力情報からの抽出根拠」を併記。MEDIUM / LOW は折りたたみ可能 |
| 次勤務への観察項目 | 確認候補をチェックボックス形式で生成し、HIGH / MEDIUM / OTHER に整理。チェック状態は保存される |
| ページ内ナビゲーション | 患者情報 / 入力 / AI要約 / SBAR / 確認優先度 / 次勤務 へ smooth scroll（`prefers-reduced-motion` に対応） |
| Brief Summary | 30〜60秒程度で口頭申し送りできる要約。患者識別→主病名→直近の変化→現在状態→入力済み医師指示→確認候補の順。手動編集可能 |
| 音声読み上げ | SpeechSynthesis による読み上げ（開始 / 一時停止 / 再開 / 停止）。Brief Summary と SBAR全文を切替可能 |
| 申し送り完了 | ステータスを 未完了 ⇄ 完了 に切替。Dashboardの集計へ即反映。AI生成結果がある場合は「AI生成ドラフトの内容を確認しました」のチェック後に完了できる |
| 保存 | 患者データ・入力・生成結果・チェック状態・完了状態を localStorage に保存。「デモデータに戻す」ボタンあり |
| コピー | Brief Summary / SBAR / リスク一覧 / 観察項目 の個別コピーと、全体をまとめた「申し送り全文をコピー」。成功時はトースト通知 |
| ダークモード | ヘッダー右上から切替。設定は保存され、初回はOSの設定に追従 |

## 技術構成

- **Next.js 16**（App Router）
- **TypeScript**（strict）
- **Tailwind CSS v4**
- **React 19**
- **lucide-react**（アイコン）
- Route Handler（`/api/handover`）によるサーバー側AI処理

追加ライブラリは lucide-react のみです。状態管理ライブラリやUIフレームワークは使用せず、React標準の `useSyncExternalStore` による軽量ストアと localStorage で構成しています。

## セットアップ方法

```bash

# 2. （任意）環境変数の準備 — 未設定でも動作します
```

## 音声入力について

- ブラウザの **Web Speech API**（`SpeechRecognition` / `webkitSpeechRecognition`）を使用しています。両方の実装名に対応しています。
- 「音声入力を開始」で録音を開始し、録音中は赤いインジケーターと停止ボタンを表示します。認識途中のテキストもリアルタイムに表示されます。
- 確定した認識結果は自由記載のテキストエリアへ追記されます。
- **音声データは本アプリのサーバーへは送信も保存もされません。**
- ⚠️ **ただし、ブラウザの `SpeechRecognition` 実装によっては、音声認識処理がブラウザ内ではなくブラウザベンダーや外部の音声認識サービス側で行われる場合があります**（Chrome / Edge はクラウド側で処理する実装です）。本アプリからは、その挙動を制御できません。
- したがって **実在患者の個人情報を音声入力しないでください。** デモでは架空情報のみを使用してください。UI上の音声入力ボタン付近にも同じ注意書きを表示しています。
- 非対応ブラウザでは「このブラウザでは音声入力を利用できません」と表示されます。
- 動作確認済み: Google Chrome / Microsoft Edge。Firefox は現時点で `SpeechRecognition` に未対応です。
- マイク使用の許可が必要です。また、多くのブラウザで `https` または `localhost` でのみ動作します。

## 音声読み上げについて

- **SpeechSynthesis API** を使用しています。
- `speechSynthesis.getVoices()` から `ja-JP` の音声を優先して選択します。日本語音声が見つからない場合はブラウザ既定の音声を使用します。
- 読み上げ対象は **Brief Summary** と **SBAR全文** から選択できます。
- 操作は 読み上げ開始 / 一時停止 / 再開 / 停止 の4つです。
- 非対応ブラウザでは「このブラウザでは音声読み上げを利用できません」と表示されます。
- OSに日本語音声がインストールされていない場合、読み上げが不自然になることがあります（macOS: システム設定 → アクセシビリティ → 読み上げコンテンツ、Windows: 設定 → 時刻と言語 → 音声認識 から追加できます）。

## AI APIについて

AI処理は **UIから完全に分離** されており、`src/lib/handover-ai.ts` が唯一のエントリポイントです。

```ts
generateHandover(input)        // 要約・SBAR・リスク・観察項目を一括生成
generateSBAR(input, risks?)    // SBAR
detectRisks(input)             // リスク抽出
generateNextShiftTasks(input)  // 次勤務への観察項目
generateBriefSummary(input)    // 口頭申し送り用の要約
```

### APIキー未設定時（既定）

`OPENAI_API_KEY` が設定されていない場合は、**モックAIエンジン**（`src/lib/ai/mock-engine.ts`）が動作します。単語の一致だけでなく、数値条件と組み合わせ条件で確認候補を抽出します。

#### 確認優先度（HIGH / MEDIUM / LOW）の意味

**患者の医学的重症度ではなく、「申し送り時に確認する優先度」です。** 診断でも重症度分類でもありません。

抽出ルールの例:

| 条件 | 確認候補と優先度 |
| --- | --- |
| 「ふらつき」等 ＋ 「夜間トイレ」等 | 転倒関連の確認 **HIGH** |
| 直近の体温 38.0℃ 以上、または入力済み医師指示の基準以上 | 体温・再発熱の確認 **HIGH** |
| 過去に 37.5℃ 以上の記録があり、直近は解熱している | 体温・再発熱の確認 **MEDIUM**（「現在発熱」とは表現せず、過去値と現在値を並記して再発熱の有無を確認候補にする） |
| SpO2 92% 以下、または入力済み医師指示の基準を下回る | SpO2値・推移の確認 **HIGH** |
| SpO2 93〜94% | SpO2値・推移の確認 **MEDIUM**（単一値の場合は「低下」と表現せず、推移・酸素投与の有無・平時値の確認候補として提示） |
| 呼吸数 25回/分以上 または 9回/分以下 | 呼吸状態の変化に関する確認 **HIGH** |
| 食事摂取量 3割以下 | 食事摂取量の確認 **HIGH** |
| NRS 7以上 | 疼痛に関する確認 **HIGH** |
| 収縮期血圧 90mmHg未満 / 脈拍 120以上 | 血圧・脈拍の確認 **HIGH** |
| ルート記載 ＋ 「自己抜去」「漏れ」「腫脹」等 | ルート・刺入部の確認 **HIGH** |
| HIGH が2件以上 | 確認優先度HIGHの重複 **HIGH** を追加 |

各項目には「入力情報からの抽出根拠」（どの数値・記載から抽出したか）が併記されます。

#### 医療安全のための設計ルール

- 診断名を断定せず、「〜の確認」「〜の確認候補」として提示します（例: 「呼吸状態悪化」ではなく「呼吸状態の変化に関する確認」、「脱水」ではなく「水分出納の確認」）。
- 新しい看護指示・観察頻度・投与基準を作りません（例: 「体温を4時間ごとに測定」ではなく「再発熱の有無と体温の推移」）。
- 閾値は**入力された医師指示に書かれている値のみ**を、表記のまま引用します。「SpO2 93%未満で酸素1L開始」という入力がある場合に限り、「現在値94%と基準93%未満の比較を確認」のように入力情報同士を突き合わせて提示します。
- 医師指示は改変せず、SBAR の Recommendation と High Priority セクションに原文のまま表示します。
- 過去値と現在値を混同しません（「昨夜38.2℃・現在36.8℃」を「現在発熱」とは表現しません）。
- 単一の測定値から状態を断定しません。時系列で低下が確認できる場合のみ「低下」と表現します。
- 医師指示のテキストは条件付きの指示であって観察結果ではないため、キーワード抽出の対象から除外しています。
- 登録アレルギーは提示のみで、禁忌薬・代替薬の提案は行いません。

### 実AI APIへ接続する場合

`.env.local` に次を設定すると、`/api/handover` が OpenAI互換APIを呼び出します。

```bash
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini          # 任意
OPENAI_BASE_URL=https://api.openai.com/v1  # 任意（互換APIを使う場合）
```

- APIキーは **サーバー側の Route Handler でのみ** 読み取られ、フロントエンドのコードやバンドルには一切含まれません。
- API呼び出しに失敗した場合はモックAIへ自動フォールバックし、デモが止まらないようにしています。
- 実装は `src/lib/ai/openai-provider.ts` に分離しているため、別のプロバイダへの差し替えも容易です。

## デモデータについて

- **12名の架空患者**（誤嚥性肺炎 / 心不全 / 大腿骨頸部骨折術後 / 糖尿病 / 脳梗塞 / COPD / 胆嚢摘出術後 / 腎盂腎炎 / 気管支喘息 / 前立腺肥大症 / 関節リウマチ / 胃潰瘍）を用意しています。
- 一部の患者にはあらかじめ転倒リスク HIGH などの患者背景と、申し送り入力の例文を設定しています。
- すべてのデータは **localStorage**（キー: `handover-ai:state:v1`）に保存され、ページを再読み込みしても保持されます。
- Dashboard の「デモデータに戻す」ボタンで初期状態へリセットできます。
- 実在の人物・症例とは一切関係ありません。

## 医療安全上の注意

> **Handover AIは看護申し送りを支援するプロトタイプです。AI生成内容は参考情報であり、最終的な判断・確認は医療従事者が行ってください。AIは診断・治療・看護判断を代替しません。**
>
> **実在患者の個人情報を入力しないでください（キーボード入力・音声入力のいずれも）。**

- 本アプリは医療機器ではなく、診断・治療の判断を行うものではありません。
- AI生成結果は「AI生成ドラフト」であり、確認前の下書きです。確認・編集のうえで利用してください。
- HIGH / MEDIUM / LOW は**申し送り時の確認優先度**であり、患者の医学的重症度や診断ではありません。
- 確認候補の抽出は入力されたテキストに対する機械的な処理であり、臨床判断の代替にはなりません。抽出されない事項が存在し得ます。
- データはブラウザの localStorage にのみ保存され、サーバーには保存されません。共用端末での利用時はご注意ください。
- 実運用にあたっては、電子カルテ連携・アクセス制御・監査ログ・院内のセキュリティ要件への適合が別途必要です。

## 今後の拡張案

- **PDF／印刷出力** — 申し送り記録の帳票化
- **多言語対応** — 外国人スタッフ向けの英語表示
